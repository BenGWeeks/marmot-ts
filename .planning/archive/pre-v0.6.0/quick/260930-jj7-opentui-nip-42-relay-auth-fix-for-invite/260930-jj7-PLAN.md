<objective>
Make the opentui example answer NIP-42 AUTH challenges so auth-required relays (relay.ditto.pub in the reproduced case) stop silently withholding data, and make the invite KeyPackage lookup robust against a relay connection that an unrelated subscription has flagged auth-required. Scope: examples/opentui only. No library src/ changes (user decision: applesauce will add granular auth controls later, so this stays small and local).

Purpose: Verified 2026-09-30 (debug.log + bun probes). At startup the app subscribes for kind-1059 gift-wraps on the 10050 inbox relays, which include relay.ditto.pub. ditto sends an AUTH challenge and CLOSED auth-required for that REQ. applesauce-relay then sets that Relay's authRequiredForRead$ to true. Because long-lived subscriptions keep the socket open, every later REQ on it (default waitForAuth true) waits for an authentication that never comes. So (a) the invitee's 5 kind-30443 KeyPackages on ditto are never returned, and (b) our own welcome gift-wraps on ditto are never readable. Secondary: the first invite attempt's invitee NIP-65 lookup timed out (10 s) because it did not hint LOOKUP_RELAYS.

Mechanics verified in applesauce-relay 6.2.1 (dist/relay.js, group.js, pool.js):
- Relay.req retries an AuthRequiredError by flipping receivedAuthRequiredForReq and, when waitForAuth is true, waiting on authenticated$. So once we authenticate, the stalled gift-wrap subscription resumes on its own.
- With waitForAuth false the REQ is sent regardless of the flag. An auth-required CLOSED is rethrown, and the group turns it into an ERROR message.
- RelayGroup.request's default completion is "5 s after the first relay EOSE, or all relays EOSE/ERROR". A relay held on auth never sends OPEN, so it cannot block the others.
- RelayPool.relay(url) emits add$ for every newly created relay. close() calls remove() per relay, which emits remove$.
- Relay.resetState() on disconnect clears challenge$ and the auth-required flags, so a reconnect yields a fresh challenge.
- rxjs is NOT resolvable from examples/opentui (pnpm strict, not a direct dependency). The helper must therefore use only the .subscribe() method of the relay/pool observables and must not import rxjs, so package.json and the lockfile stay unchanged.

Output: new relay-auth helper + test, RelayPool wrapper wiring, setup.ts signer hand-off, two targeted controller fixes, README note.
</objective>
